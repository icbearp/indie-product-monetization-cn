# 定价、成本与验证

## 从价值和成本选择候选价

把用户节省的时间、减少的错误或新增的能力写成待验证价值，不直接折算成保证回报。成本决定可持续范围，用户价值与替代方案决定价格接受度。访谈可用不同价格和取舍探询意愿，但口头接受不等于成交。

按目标使用频率估算每个付费用户周期内的低、常见和高用量，列出单位、依据与未知项：

- 可变服务成本：云、模型/API、存储、第三方调用。
- 交易成本：支付费用、实际适用的平台费用、退款损失。
- 交付成本：支持时间、维护工时；与可变现金成本分开列。
- 固定投入：研发和基础服务，不随意伪装成零成本。

每周期贡献额 = 相同口径的净收入 − 该周期可变交付成本。注明税、退款和手续费是否已在净收入扣除，避免重复减。币种一致，年费现金流与月度收入分开；买断收入不计为订阅 MRR。

本地工具可以买断，但要定义版本升级和支持范围。长期云端成本较高时不承诺无限终身使用；可以比较独立额度、按量或服务订阅。用户自带 API 密钥仍有支持与维护成本。

提出少量差异明确的收费方案：适用用户、金额/币种/扣款周期、权益、限制、试用方式、续费与取消、成本假设、选择理由、验证方法。没有数据时标“候选”，不是已验证最优。

## 衡量同一个用户旅程

先按产品节奏选观察窗口，再定义进入条件与去重键。免注册本地工具不强行以注册用户为分母；不能稳定识别用户时使用安装实例等可观测单位，注明重装、跨设备和跨分身偏差。

| 指标 | 最低定义要求 |
|---|---|
| 首次任务成功率 | 成功完成真实任务的合格实例 / 进入该路径的合格实例；明确成功条件 |
| 首次价值耗时 | 从指定入口到首个真实结果；失败和未完成单独报告，避免只看成功者 |
| 升级购买率 | 完成真实付费的去重对象 / 实际看到对应升级入口的合格对象 |
| 试用转付费 | 在规定窗口内付费的试用对象 / 已经过完整试用及后续观察窗口的试用对象 |
| 留存/续费 | 明确队列、回访/有效使用事件或续费到期条件；未到观察期不算流失 |
| 退款与投诉 | 明确退款按订单还是买家，投诉来源、样本量和窗口 |

事件按需要设计，例如 `setup_completed`、`task_succeeded`、`upgrade_viewed`、`payment_confirmed`、`entitlement_activated`。这些是建议事件名，不代表产品已埋点。记录版本、方案、发生时间和必要去重信息；避免上传帖子正文、联系人列表、身份凭据等与实验无关内容。远程分析须符合用户选择和产品披露，不能因做商业化默认开启遥测。

## 实验卡

每次写清：假设、目标对象、改动、主指标、退款/留存/任务失败等保护指标、分组单位、观察窗口、停止条件和回退方案。

有足够流量才考虑稳定随机分组，避免同一用户在多个版本之间跳变。先确定基线、最小有意义差异和可接受误差再算样本。若流量小，可先观察真实任务、访谈并提供单一候选报价，报告样本限制。不得把几次正面反馈称为显著转化提升。

激活行为与后续留存须使用分离的时间窗口，相关性只支持候选假设。修复付款故障通常是所有版本共有的基线，不为实验让部分人继续失败。涨价须核对既有承诺和通知条件，不自动迁移已付费用户。
